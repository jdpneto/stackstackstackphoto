# Golden Corpus + SSIM/ΔE Metrics

**Status:** Approved design (autonomous run, recommended options). Delta TL;DR #5; bible §7.5/§18 — the cross-platform divergence guardrail, built now so it exists before Android starts.

## 1. Goal

Pin every look's full-pipeline output against stored reference images with PSNR/SSIM/ΔE tolerances, runnable in CI on every engine change; add the missing SSIM and ΔE metrics.

## 2. Metrics (engine, `Metrics.swift`)

- **SSIM** — `Metrics.ssim(_ a: PixelImage, _ b: PixelImage) -> Double`: standard SSIM on Rec.709 luma, 8×8 box windows (stride 4), K1=0.01 K2=0.03, L=1 (linear-light [0,1] domain), mean over windows. Deterministic, no platform deps.
- **ΔE (CIE76)** — `Metrics.meanDeltaE(_ a: PixelImage, _ b: PixelImage) -> Double`: linear-sRGB → XYZ (D65) → Lab → ΔE76 per pixel, mean. CIE76 (not CIEDE2000) per YAGNI — it's a regression tripwire, not a perceptual instrument; the formula is pinned in code comments for the Android port.
- Unit tests: identity image → SSIM 1 / ΔE 0; known perturbations move the metrics in the right direction (small noise → SSIM < 1 but > 0.9; a hue shift → ΔE grows while PSNR can stay high — the ΔE-catches-color case).

## 3. The corpus

Two tiers, both always-on (fast — no env gate):

1. **Synthetic Bayer sequences** (engine-generated, deterministic): a 96×64 textured scene rendered to RGGB mosaics with per-frame translation jitter + per-frame noise (seeded LCG — NO SystemRandom), 6 frames. One sequence feeds all four reducer looks via `Pipeline.reduce`; a focus-bracket variant (band-sharp frames, known drift — the existing chain fixture generator) feeds `FocusStacker`.
2. **The real device brackets** (already in `Resources/depth-brackets`) stay under the opt-in heavy gate as-is.

**Reference outputs**: golden PNGs committed under `Tests/StackEngineCoreTests/Resources/golden/` (one per look: `noiseReduction.png`, `smoothMotion.png`, `lightTrails.png`, `lowLightBoost.png`, `depth.png` — ~96×64, a few KB each), generated by the pipeline itself at authoring time via a temporarily-enabled regeneration path: `SSS_REGENERATE_GOLDENS=1 swift test --filter GoldenCorpusTests` writes them to /tmp for manual copy-in (the test SKIPS comparisons while regenerating, so a stale-golden state can't silently self-bless).

**Tolerances** (pinned constants in the test file, the contract for Android): PSNR ≥ 45 dB, SSIM ≥ 0.98, mean ΔE ≤ 1.0. Loose enough for cross-platform float drift, tight enough that an algorithm change trips them.

## 4. What this is NOT (yet)

Not a RAW-file corpus (synthetic mosaics are bit-reproducible and need no binary assets beyond the tiny goldens); not perf benchmarks (§16 targets remain open in the delta); CIEDE2000 deferred.

## 5. Testing/process

`GoldenCorpusTests` runs in the default suite (fast). Delta TL;DR #5 marked done-with-scope; bible §18 gets a status note. Regeneration procedure documented in the test header.
